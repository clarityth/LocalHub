# LocalHub - 포트폴리오 및 발표 자료 기술 문서

본 문서는 면접 포트폴리오 기재 및 팀 프로젝트 발표 슬라이드 제작에 활용할 수 있도록, 프로젝트에서 해결한 핵심 기술적 챌린지와 설계 주안점을 정리한 문서입니다.

---

## 🚀 1. 시스템 아키텍처 개요
- **Frontend**: Vue.js 3 (Composition API), Vite, Leaflet.js
- **Backend**: FastAPI, SQLAlchemy (ORM), Pydantic
- **Database / Vector DB**: SQLite, FAISS (Facebook AI Similarity Search)
- **AI Integration**: OpenAI (gpt-4o-mini, text-embedding-3-small)
- **Deployment**: Netlify (Front), Render (Back) 연동 환경

## 💡 2. 주요 기술적 성과 (Technical Highlights)

### ① SSE(Server-Sent Events) 기반 실시간 스트리밍 RAG 챗봇
- **문제점**: RAG 검색(FAISS)과 LLM 추론이 순차적으로 발생하여 초기 응답 지연(TTFB)이 길고 UX가 저하됨. (특히 서버리스 환경 배포 시 Timeout 우려)
- **해결 방안**: FastAPI의 `StreamingResponse`와 Generator를 활용하여 OpenAI의 응답을 Chunk 단위로 쪼개어 실시간으로 프론트엔드에 PUSH하는 SSE 아키텍처 구현.
- **결과**: 사용자는 타자를 치듯 실시간으로 챗봇 답변을 확인할 수 있어 체감 대기시간을 획기적으로 단축시켰으며, 메타데이터(참고 장소, 출처)와 텍스트를 분리 전송하는 자체 프로토콜을 구현함.

### ② 유연한 데이터 스키마 설계 (Flexible Schema Pattern)
- **문제점**: 공공데이터(한국관광공사 TourAPI)는 '관광지', '음식점', '축제' 등 카테고리마다 고유 필드(예: 주차 가능 여부, 대표 메뉴 등)가 천차만별이어서 고정된 RDBMS 컬럼으로 관리하기 어려움.
- **해결 방안**: 공통 핵심 필드(좌표, 주소, 이미지 등)는 정규화된 컬럼으로 분리하여 인덱싱을 태우고, 카테고리별 동적 필드는 `type_fields_json`이라는 Text 필드에 JSON 직렬화하여 적재.
- **결과**: DB 마이그레이션(Schema Update) 없이도 새로운 카테고리의 공공데이터를 유연하게 수용할 수 있는 확장성 높은 DB 구축.

### ③ 식별자 없는 익명 환경의 어뷰징 방지 (Fingerprinting)
- **문제점**: 요구사항에 따라 로그인/회원가입이 존재하지 않으므로, 커뮤니티 게시판의 '좋아요' 기능이 무한정 악용될 소지가 있었음.
- **해결 방안**: 사용자의 HTTP Request 정보를 바탕으로 `IP 주소`와 `User-Agent`를 조합한 뒤 **SHA-256 단방향 해시** 함수를 거쳐 클라이언트 고유 식별자(`fingerprint`)를 동적 생성. 이를 SQLite의 `UniqueConstraint` 제약조건과 결합하여 중복 투표 원천 차단.
- **결과**: 쿠키나 로컬 스토리지를 지우고 재시도하는 기초적인 어뷰징을 백엔드 DB 레벨에서 성공적으로 방어해 데이터의 신뢰성 향상.

### ④ 하이브리드 컨텍스트 검색 파이프라인
- **문제점**: RAG를 위한 PDF 임베딩 정보 외에, DB에 쌓이는 실시간 '사용자 게시글'과 '장소 데이터'도 AI가 알고 답변해야 했음.
- **해결 방안**: 
  1. **FAISS 벡터 검색**: 지역 관광 가이드(PDF) 문서를 임베딩한 뒤 챗봇 질문과 코사인 유사도 연산 (Semantic Search).
  2. **SQLite 풀텍스트 유사 검색**: 질문을 형태소(Token) 단위로 쪼개어, 게시판의 제목/내용/장소명에 대해 `LIKE` 쿼리 수행 (Keyword Search).
- **결과**: 벡터 검색 결과와 키워드 쿼리 결과를 하나의 프롬프트 컨텍스트 창(Context Window)에 통합 주입함으로써, **사전 지식(가이드북)과 실시간 동향(게시판)을 모두 파악하는 AI 챗봇**을 완성함.

### ⑤ Premium UX 및 보안(Sanitization) 강화
- **문제점**: 공공데이터 응답값 내부에 `<br>`, `<b>` 등 불필요한 원본 HTML 태그가 오염되어 있었음.
- **해결 방안**: 백엔드 응답 직렬화 직전에 정규식(`strip_html`) 필터를 거쳐 순수 텍스트만 추출. 동시에 프론트엔드에서는 `marked` 라이브러리로 AI 마크다운을 렌더링하고, XSS 공격 방지를 위해 `DOMPurify`로 입출력을 소독(Sanitization) 처리.
- **결과**: Glassmorphism UI 테마와 결합하여 상용 서비스 수준의 안전하고 미려한 프론트엔드 뷰 완성.

2. **핵심 뷰어 (Showcase)**: "시연 영상을 보시죠. 실시간 스트리밍으로 챗봇이 답변을 하며, 답변 하단에는 참조한 공공데이터 뱃지가 노출됩니다."
3. **기술적 챌린지 (How we solved)**: "로그인이 없는 익명 서비스의 한계를 극복하기 위해 Fingerprinting 기법을, 공공데이터의 불규칙한 스키마를 다루기 위해 Flexible Schema 전략을 채택했습니다."
4. **확장 가능성 (Future)**: "현재 대전/충청권에 국한되어 있지만, 구축된 파이프라인을 통해 타 권역 데이터만 밀어넣으면 전국 단위 확장도 DB 변경 없이 즉시 가능합니다."
